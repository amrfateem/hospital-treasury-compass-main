
- Backups (`backup.server.ts`, `paths.server.ts`) write integrity-checked SQLite snapshots + additive file mirror to `<app>/Backups`, `%PUBLIC%\Documents\AlRahmaHospitalBackups\<PC>` and extra folders set in Settings; on start, hourly when data changed, at least daily, manual; 60-day retention. SQLite uses WAL + `synchronous=FULL` so power cuts lose at most the in-flight write. On open, `recovery.server.ts` swaps a corrupt DB for the newest healthy snapshot; `tools\restore-backup.cmd` restores manually. Tested in `backup.test.ts`.
- The director's backup warning (`BackupHealthAlert` in AppShell) re-checks on page change, 20 s after start, every 10 min and on the `BACKUP_CHANGED` browser event; a recovery warning shows until the director clicks «تمام، راجعت» (`acknowledgeRecovery` stamps `acknowledgedAt` in `recovery-log.json`), and a data folder under the OS temp dir (opened from inside the ZIP) gets its own warning.
- Old-system SQL imports (`src/lib/legacy`) use the pure `importLegacyData` op for identified active document records and `saveState`'s synchronous side-effect callback for patient/medical/source rows in the same CAS transaction, so partial imports roll back. Signed `revenues` alone supplies receipts/reversals; `paid` supplies expenses, never post overlapping service/sales/pays_out amounts again. Preserve every source row privately, flag unknown meanings for review, keep original dates, use add-only target IDs and durable source markers to avoid duplicates or resurrecting edited/deleted records, respect closed years/days, require director and a successful pre-import backup, and never expose raw credential/configuration fields. Covered by `migration.test.ts` and `legacy-import.server.test.ts`.
- Full and changed-chunk reads use the session-protected `/api/hospital-state` JSON endpoint with `viewFor` redaction and no-store; mutation ops stay typed RPC. This avoids RPC serializer limits after importing hundreds of thousands of records while retaining changed-only sync and the durable device cache/outbox.
