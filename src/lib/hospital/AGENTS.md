# Hospital domain rules

- Permission levels: `ADD_OPS` in `ops.ts` marks create-only ops as "add" (an upsert on an existing record needs "edit"); `requiredLevel` resolves it and `opsBySection()` feeds the permissions screen, so new ops show up there automatically.
- Approvals are role-based on top of sections: every decide op (payment/petty/purchase/store requests, receipt changes) calls `requireApprover` → `canApprove` (finance role only, never on its own request; the director only on a finance-role request). Requests store `requestedById`/`requestedRole` for this. Direct money-out (`addExpense`, manual out transactions, direct stock out) is limited by `canSpendDirectly`; everyone else goes through a request.
- Department store requests (`issueOrders`) flow pending → approved/rejected → issued; stock moves are created only by `deliverIssueOrder` (section "stock"). Older saves without a status are normalized to "issued".
- The general store catalog (`stock-catalog.ts`: categories + consumables per department) is configuration merged once via `settings.stockCatalogVersion` (bump `STOCK_CATALOG_VERSION` when adding entries); department consumption math is pure in `store-report.ts`. Both covered by `approvals.test.ts`.
- Petty cash: staff raise `pettyRequests` (pending → approved/rejected → paid); `payPettyRequest` creates the petty transaction with `ref` = request id, and deleting that transaction puts the request back to approved. Waiting-request counts for badges come from `approvals.ts` so every request type is counted in one place.
- Receipt desks (`RECEIPT_DESKS` in `catalog.ts`) map a receipt section to a department; the desk is derived with `deskOf`. A receipt's price list comes only from `servicesForDesk` (the department's own services + chosen clinic; shared no-department services kept in a separate group; nothing until a department is chosen) so departments never mix; covered by `desk-services.test.ts`. Invoice treasury entries come from `withPatientInvoice`/`withSupplierInvoice` and are removed together via `ref`.
- Employment contracts: draft → printed → signed on paper with a pen, recorded via `signContract` (optional scan as a private file; no on-screen signing) → ended; signing copies job/department/salary onto the employee for payroll. ETA e-invoices are locked after submission.
- Notifications: `notifications.ts` flattens every request type into notices (approver: `waitingForMe`; requester: `myRequests`); the bell/panel and decisions (`decideNotice`) use it, so a new request type is added there once. The "seen" marker is per device (localStorage).
- Receipt-printer prefs are per device (localStorage) because the printer belongs to the PC.
- One cash treasury: all cash lives in the main treasury (`MAIN_BOX_ID`); only bank accounts are separate boxes. Old sub-box/petty records are folded into main by `normalizeDB`; desk roles collect only on their own open shift and `viewFor` shows them only their own shifts. Who collected what is derived from shift ownership in `treasury-summary.ts`; petty spends post straight from main (no top-ups). Covered by `treasury-summary.test.ts`, `staff-controls.test.ts`, `approvals.test.ts`.
- The revenues/expenses/petty management report (`income-expense.ts`) is built only from journal lines so it always equals `incomeStatement` for the same dates; covered by `income-expense.test.ts`.
- Daily closing (`daily-closing.ts`, page `/daily-closing`): days with main-treasury movement close in date order; a closing freezes a snapshot (opening/in/out/closing, cash expected vs counted, collectors) and `runOp` refuses any main-treasury transaction/transfer dated on or before the last closed day (`lockedDayChange`; director "system" ops exempt). Only the latest closed day reopens, via `requestDayReopen` → `decideDayReopen` (finance approver; director direct); the old record stays as "reopened". Desk views get closings with totals blanked. Covered by `daily-closing.test.ts`.
